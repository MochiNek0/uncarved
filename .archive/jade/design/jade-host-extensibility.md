# 设计：jade 宿主层的可扩展性

> 状态：第 2 节已实施（2.3 中 Shift+Tab 一项保留在宿主，见 2.3 的说明） · 2026-11-05
>
> 范围：只涉及 jade（`apps/jade`），不改内核。
>
> 起因：想写一个"一轮结束后给出下一条消息建议，灰字显示，Tab / → 接受，用自己的小模型生成"的插件，发现做不到。盘点之后发现，问题不只是缺一个接口，宿主层整体没有遵守插件层的原则。

## 1. 原则

> **内核不可变；Agent 行为全部可以代替；界面只开放少数明确的接口；想要完全不同的界面，就换一个宿主。**

这条原则分四个层次：

- **内核**：不可变，见 CONSTITUTION。
- **Agent 行为**：包括工具、提示词、上下文、模型、关卡，以及计划模式、续写、重试这类流程。这一层**全部开放**，内置功能只用公开的插件接口实现，所以内置插件能做的，第三方插件都能做，也都能代替。这一层的接口都是数据进、数据出，多个插件之间的组合规则清楚，开放的成本低。
- **界面**：**不追求每个零件都能改**。界面上的东西很难组合：两个插件同时要 Tab 键、同时要往输入框里画东西，只能靠优先级规则硬裁。而且每个接口都是长期的兼容承诺。所以界面只开放少数接口，每一个都要有明确的需求。
- **宿主**：可以整体换掉。uncarved 内核是一个库，`Screen` 已经有终端界面和纯文本两种实现。要的界面和 jade 差别很大时，写一个新宿主，复用内核和插件。

由此推出两条规则：

1. **宿主里不放 Agent 行为。** 宿主只负责显示、输入、会话切换。宿主越薄，换宿主越容易。
2. **一个界面接口满足下面两条，才开放：**
   - 至少有一个真实的需求；
   - 有内置功能用它实现。

   拿不准的时候先不开放。晚点开放没有代价，开放了再收回来会弄坏别人的插件，0.1.3 删除 `suggest` 付出的就是这个代价。

## 2. 要做的

### 2.1 去掉显示上的特殊待遇（已实施）

> 实施说明：和下面的设计有三处不同。一是 `jade/shell` 的进度本来就是通用的 `{ text }` 格式，不需要 `progress`，只有 `jade/task` 用它。二是"调用时显示的内容、不显示结果"做成了 `ToolRenderer.call` 和 `result` 返回 `null`；`result` 多收一个 `toolUseId`，好让 `task` 把运行中记下的子 Agent 调用放进结果里。三是 `jade/policy/reviewed` 只用来统计用量，不需要渲染器：现在任何插件事件 `data.usage` 里的用量都计入本会话，`transcript.ts` 不再按事件类型统计。

现在 `ui/transcript.ts` 按事件类型和工具名，写死了内置插件的显示：

- `jade/compact/compacted`、`jade/compact/trimmed`、`jade/checks/checked`、`jade/policy/reviewed`（`transcript.ts:412–447`）；
- `todo_write` 调用时显示清单、不显示结果（`transcript.ts:333`）；
- 工具进度只认识 `ShellProgress` 和 `TaskProgress`，其他工具只能用 `{ text }` 格式（`transcript.ts:272`）。

这**违背了已有的承诺**：文档说第三方可以代替 `jade/compact`，但代替之后，它的事件就不显示了。

改法：在 `renderers` 上补三项能力，内置插件改用它们。

| 能力 | 用途 | 改用它的内置插件 |
|---|---|---|
| 事件渲染：`{ event: "<id>/<type>", render(data) }` | 把插件自己的事件显示成一行，可以带展开后的详情 | `jade/compact`、`jade/checks`、`jade/policy` |
| `ToolRenderer.progress(update)` | 把工具的进度更新显示成一行 | `jade/shell`、`jade/task` |
| `ToolRenderer` 增加"调用时显示的内容"和"不显示结果" | 调用工具时就显示内容，结果不再重复 | `jade/todo` |

插件只能渲染自己命名空间下的事件，和现在"只能渲染自己的工具"一致。

**验收标准**：`transcript.ts` 里不再出现任何内置插件的事件类型或工具名，显示效果不变。

### 2.2 `ctx.complete` 可以指定模型（已实施）

> 实施说明：宿主经 `JadeOptions.savedModel` 按名字解析 `models.json`（`ui/configure.ts` 的 `savedModelEnv`）。`@uncarved/provider-anthropic` 增加了 `apiKey`、`baseURL` 选项，jade 从 env 传入，否则保存的 Claude 服务会读到当前 `process.env` 里的密钥。`jade/task`、`jade/compact` 改用公开接口这一项还没做：它们需要带工具的完整请求，`ctx.complete` 不够用，等 2.1 和 2.3 时一起考虑。

```ts
ctx.complete({ prompt, model: "<在 /model 里保存过的模型名>" }, signal)
```

- 不写 `model` 时，行为和现在一样，用会话当前的模型。
- 指定的模型用 `/model` 里保存的服务配置，key 从 `$JADE_HOME/.env` 读。**插件拿不到 key**，也不用自己处理 key。
- 指定的名字不存在时抛错，错误信息里列出可以用的名字。
- `jade/task`、`jade/compact` 现在是宿主通过 `JadeOptions.provider` 把 provider 传进去的（`distro.ts:259`、294），改成用公开接口。

**验收标准**：`jade/compact` 只用 `ctx.complete` 调模型。

### 2.3 把 Agent 行为从宿主挪进内置插件（已实施）

> 实施说明：两项能力做成了 `plugins/turns.ts` 的 `TurnParticipant`（`beforeMessage` 只附加：`notes` 放在用户的话前面、`blocks` 放在后面；`afterTurn` 返回 `retry`、`continue` 或 `say`），只有内置插件能提供，宿主按内置插件的顺序问。计划模式的两项在 `jade/policy`，续写是新的内置插件 `jade/continue`，溢出重试在 `jade/compact`，`@` 附件是新的内置插件 `jade/mentions`。现在 `say()` 只拼消息，`drive()` 只是"跑一轮、问下一步"的循环。
>
> 和设计的不同：**Shift+Tab 留在宿主**。切换模式要用宿主的整套模式管理（`/mode`、运行中先记在 pendingMode、记进 `.env` 的 JADE_MODE、状态栏），只把按键挪进 `jade/policy` 还得把这些都开放给它，收益只是换个地方注册按键，不值得。`say` 的 `mode` 也是同样的原因：计划被批准后由宿主切换模式。
>
> 小的行为差异：重新加载会话（`/search` 改配置后的 reload）后，`jade/policy` 是新的实例，计划模式下会再告诉模型一次"现在是计划模式"；以前只在 `/clear`、`/resume` 后重新告知。溢出重试现在在续写之后也会检查（每次输入仍然最多一次），以前只检查第一轮。

| 现在写在 `main.ts` 里的行为 | 挪到哪里 |
|---|---|
| 计划模式的告知：`announceMode`（1113） | `jade/policy` |
| "执行这个计划？"：`offerPlan`（1131） | `jade/policy` |
| 输出被截断后自动续写，最多 3 次：`drive()`（1196） | 新的内置插件 `jade/continue` |
| 上下文溢出后压缩并重试：`drive()` | `jade/compact` |
| `@` 引用的文件随消息附上：`say()`（1161） | 新的内置插件 `jade/mentions` |
| Shift+Tab 循环切换模式：`cycleMode` | `jade/policy` 注册的按键 |
| 会话标题取第一条消息的前 80 字：`say()`（1155） | 不挪，留在宿主 |

为此需要两项能力。**这两项先只给内置插件用，不写进公开文档**，等第三方真有需求再开放：

1. **轮次结束后让插件再发起一轮**，用来续写和溢出重试。插件在 `turn.ended` 的 observe hook 里只记下"要继续"，宿主在这一轮结束后发出带 host note 的下一轮。这样不需要让 hook 自己驱动运行时。
2. **用户消息发出前附加内容**，用来做 `@` 附件。**只附加，不改写用户的原话。**

`Shift+Tab` 需要按键规格支持 `shift+tab`，只允许 `jade/policy` 注册。

**验收标准**：`say()` 和 `drive()` 只剩"发消息、跑一轮"这两件事，现有测试通过。

### 2.4 输入框提示（满足建议提示插件这个需求）（已实施）

> 实施说明：按下面的设计实现，另外加了一项：用户希望建议插件用自己设置的地址、密钥和模型，所以 `ctx.complete` 的 `model` 除了保存过的模型名，还可以是插件给出的服务 `{ kind, baseURL?, apiKey?, model }`（只支持内置的三种格式），并加了 `ctx.listModels(service)` 让插件列出可选的模型。这种写法下密钥由插件自己保存。示例插件是 `apps/jade/examples/plugins/suggest`。进程外插件暂时不能设置提示。

只开放一个窄接口：

```ts
ctx.input?.hint(text: string | undefined)
```

- **显示**：输入框为空时，提示代替占位文字，灰色显示。
- **接受**：只在两种情况下把提示变成真实文字。按键 Tab、→ 本身不开放给插件，由宿主处理。
  - 输入框为空时按 Tab；
  - 光标在行尾时按 →。
- **消失**：用户一开始打字、提交消息、换会话，提示就去掉。
- **权限**：只给用户层插件，和 `ctx.input` 一样。`jade -p` 时没有。
- **冲突**：同一时间只显示一条提示，后设置的覆盖先设置的。

"一轮结束后生成建议"这个时机，用已有的 `event` hook 监听 `turn.ended` 就能拿到，不需要新的扩展点。

**验收标准**：用 2.2 和 2.4 写出建议提示插件，作为 `examples/plugins/suggest`，不需要任何专门为它加的接口。

## 3. 暂缓的

下面这些等至少有一个真实的需求，并且有内置功能能用它实现时，再考虑开放。

| 项 | 暂缓的原因 |
|---|---|
| 通用的按键分层分发：插件接管 ↑↓、Tab 等 | 和历史记录、补全菜单抢按键，用户很难弄清楚按键为什么失灵 |
| 补全来源接口：`/命令`、`@文件`、`#issue` 这类补全 | 有内置功能可以用它实现，但没有第三方需求 |
| 工具和 hook 里向用户提问（`ctx.ui`） | `ask_user` 和编辑后检查的确认继续由宿主私下传入 |
| 常驻面板 | 工作量大，需求不明确 |
| 插件注册命令行子命令 | 需要在不创建会话的情况下加载插件 |
| 粘贴处理、状态栏段落的颜色和优先级、桌面通知改成插件 | 收益小 |
| 把 `/help`、`/plugins` 改成内置插件 | 不影响第三方能做什么，有空再做 |
| 第三方的"消息发出前"扩展点 | 2.3 的能力只给内置插件。第三方想给消息附加信息，用 `context.project`、`context.build` 就行 |

## 4. 保持封闭的

| 项 | 理由 |
|---|---|
| 审批的决定和审批对话框 | 安全边界，见 I-7；插件只能让审批更严，可以用 `renderers.preview` 定制预览内容 |
| 项目层插件替用户说话、改输入框 | 克隆仓库不等于授权它替你操作 |
| Ctrl+C、Esc 的中断和退出 | 插件出问题时，用户必须还能停下来、退出 |
| 终端控制序列过滤（`terminalSafe`） | 插件不能搞乱终端 |
| 编辑键、鼠标选中复制、历史 ↑↓ 和 Ctrl+R | 开放的收益小，出错的代价大 |
| 改写用户的原话 | 用户看到的和模型收到的必须一致 |
| Markdown 渲染、标题区、轮次结束的提示 | 宿主的职责 |

## 5. 和 0.1.3 删除决定的关系

`jade-plugin-lifecycle.md` 第 9 节删掉了 `responder`、`suggest`、`beforeSend`。

- **`responder`**：替用户回答审批，继续删除，和第 4 节一致。
- **`suggest`**：由 2.4 的 `ctx.input.hint` 代替。区别是：`suggest` 由宿主决定何时调用插件；`hint` 由插件自己决定何时设置，时机用已有的 hook 拿到。宿主不需要知道"建议"这个概念。
- **`beforeSend`**：不恢复。2.3 只给内置插件"附加"的能力，不给"改写"的能力。

## 6. 顺序

1. 2.2 `ctx.complete` 指定模型：改动最小，单独就有用。
2. 2.4 输入框提示，再写 `examples/plugins/suggest`：建议提示的需求到这一步就满足了。
3. 2.1 去掉显示上的特殊待遇：修复"代替 `jade/compact` 之后它的事件不显示"这个问题。
4. 2.3 把 Agent 行为挪出宿主：改动最大，放在最后，每挪一项单独提交。

每一步都要同步更新 `apps/jade/docs/plugins.md` 和测试。
