# 设计：computer-use 插件（jade/computer）

> 状态：最小版本已实现 · 2026-11-27。第 4 节是实测数据，第 5 节是接下来可能要做的事
>
> 相关：[jade.md](./jade.md)；宪法 I-4（投影）、I-5（日志可重建）、I-6、I-9（可中断）

## 1. 目标

让 jade 能看屏幕、操作键鼠：最终能玩简单的游戏、回复消息、操控浏览器。同时作为一次学习：computer-use 怎么实现，在哪些地方能优化，优化的效果要用数字比较。

不改核心，全部在插件 `apps/jade/plugins/computer` 里。

## 2. 现在的实现

| 文件 | 内容 |
|---|---|
| `windows.ts` | 常驻的 PowerShell 进程，用 `Add-Type` 编译一段 C#，按行收命令、按行回结果，不需要装任何依赖。进程先声明 per-monitor DPI aware，截屏和点击都按物理像素算。只截主屏。等待中被取消或超时就结束进程，下次再启动 |
| `tool.ts` | `computer` 工具：`screenshot / click / type / key / scroll / wait`。`action` 是一个动作，`actions` 是一串（最多 20 个），整串做完才截一张图。截图长边缩到 1280，坐标按最近一次截图的比例换回屏幕坐标。参数全部检查完才碰屏幕 |
| `index.ts` | 设 `JADE_COMPUTER=1` 且在 Windows 上才注册；模型不能看图片时（`models@1` 的 `vision`）请求里不给这个工具 |

- `effect: "external"`：每次调用都经过 jade/approval。截图也是，它会把屏幕内容发给模型提供方。
- 急停：每个键鼠动作之前看鼠标是不是在屏幕左上角，是就不执行，告诉模型停下。
- 截屏：第一次约 2.3 s（编译 C#），之后约 110 ms；1920×1080 缩到 1280×720 的 PNG 约 330 KB。

## 3. 设计上的取舍

- **自定义工具，不用 Anthropic 原生的 computer use 工具类型**：原生的要 provider 支持非普通 schema 的工具定义，换到 openai 的 provider 就用不了。先用自定义工具，跑通以后再比较。
- **一串动作合成一次调用**：每轮都要重发系统提示词、工具定义和之前的截图，轮数是成本的大头（见第 4 节）。代价是列表里的点击看不到前面几步造成的变化，工具描述里要求只点截图里见过的坐标。
- **默认不开**：它能操作整台电脑，写代码时不该出现在模型面前。

## 4. 实测

任务"打开记事本，输入 hello"，模型 egg-alpha-004（经中转）：

| | 一次一个动作（auto） | 一串动作（yolo） |
|---|---|---|
| 轮数 | 5 | 3 |
| 主模型输入 | 41.0k | 24.0k |
| 主模型输出 | 151 | 357（这次带了 thinking） |
| 审批审查 | 3.1k 输入 / 813 输出 | 0 |
| 日志 | 1.45 MB | 0.52 MB |

- 每轮固定部分（系统提示词 + jade 全部工具定义）约 7k，3 轮约 21k，占输入的 88%。每张截图只有约 800–900 tokens。
- auto 模式的审批审查每次约 1k tokens，输出比主模型还多。
- 缓存命中不稳定：同样的前缀，有的轮读到 6–9k，有的轮是 0，`cacheWriteTokens` 一直是 0。provider-anthropic 的缓存标记是对的；工具调用 ID 是 `chatcmpl-tool-…`，推测中转背后是 OpenAI 兼容的后端，前缀缓存按副本分开。未证实。

## 5. 接下来可能要做的

按建议的顺序。

### 5.1 先弄清楚成本

1. **换 provider 验证缓存**：同一个任务换正规的 Anthropic / OpenAI provider 跑。缓存稳定命中时，每轮重发的部分按约 1/10 计费，决定 5.2 有多急。
2. **评测台**：5–10 个能重复跑的固定任务（记事本、计算器、扫雷开局、本地网页填表单），自动记成功与否、轮数、输入/输出 token、耗时。后面每项优化都拿它比较，不凭感觉。

### 5.2 降每轮的固定成本

3. **computer 模式**：操作电脑时不带写代码的工具，系统提示词也换成短的，把每轮的 7k 降下来。不依赖缓存，任何 provider 都有效。要想好怎么切换（命令、模式、还是子会话）。
4. **审批**：给 `computer` 一条"总是允许"的规则，或者让审查只看批量动作的摘要。省掉每次约 1k tokens 和一次等待，代价是没人把关。

### 5.3 截图

5. **只保留最近 N 张截图**：用 `context.build` 把更早的截图整块省略（I-4、I-6 允许）。5 步的任务不明显，玩游戏这种几十步的任务是关键。
6. **JPEG 代替 PNG**：比较 token、日志大小、模型点击的准确率。
7. **截图上的辅助**：画出鼠标位置、叠坐标网格，看点击准确率有没有变化。
8. **日志膨胀**：图片都以 base64 写进 jsonl（I-5），省不掉。以后可以让 store 把图片单独存放，日志里只留引用。

### 5.4 给模型更好的信息

9. **UI Automation**：读 Windows 的控件树和文字，给元素编号让模型按编号点（set-of-marks），减少靠像素猜。也是回复消息（微信这类桌面程序）的基础。
10. **浏览器走 CDP**：`screenshot` 插件已经有 CDP 的连接代码，可以读 DOM 和可访问性树，按元素操作。截屏点击只留给浏览器之外的程序。

### 5.5 动作和交互

11. 补上 `drag`、`move`（悬停）、长按。
12. 智能等待：等界面稳定（连续两张截图相同）代替固定的 0.5 s。
13. 游戏：模型每走一步要好几秒，只适合回合制或节奏很慢的游戏（扫雷、2048、纸牌）。快的游戏要另想办法（例如模型只定策略，本地程序执行）。

### 5.6 范围

14. 多显示器。
15. macOS / Linux 的驱动（`Driver` 接口已经和平台无关）。
16. 抢键鼠的问题：模型操作时用户没法同时用电脑，焦点可能切到 jade 的终端上。可以考虑在虚拟桌面或单独的会话里跑。
